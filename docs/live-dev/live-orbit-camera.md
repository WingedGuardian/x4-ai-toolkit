# Bounded native orbit and camera observations

This optional extension supplies `x4-orbit-camera-v1` with four closed actions: `camera_observe`, `orbit_start`, `follow_start`, and `orbit_stop`. It is partial camera infrastructure, not completion of exact camera-pose acceptance. No game action, deployment, focus change or capture has been run for this unit.

`scripts/live_orbit_extension.py:prepare()` returns an MD candidate and its Lua loader as bytes plus a source-bound inventory. It does not apply them. The loader uses the supported extension catalog and owned MD channel. It depends on the game's existing `OrbitParameterized` cutscene; no Egosoft cutscene data is redistributed. Shared helper composition remains a separate integration step.

`orbit_start` takes one helper-issued ship token and integral `distance` (10–100000), `elevation` (-100000–100000), and `duration` (1–30). These are requested native cutscene parameters, not measured world distance or pitch. The MD resolver requires a live ship in the player's sector. Preparation retains target, parameters, world/session identity, sector, player container and occupied ship. Execution consumes once and checks them again. It refuses an existing owned orbit, fullscreen cutscene, conversation or fullscreen menu. The start must be at least 1.2 simulated seconds and at most 10 simulated seconds after preparation; the Lua preparation also has a conservative ten-second UI-clock lifetime. These clocks are not equated. The gap is a native-derived precaution and sampled refusal, not proof that no foreign cutscene started anywhere in the interval.

The native result handle remains owned by the MD record. A child cue requests stop on that exact handle after the bounded duration. `orbit_stop` accepts only the original local start request ID whose handle was actually observed. It prepares and consumes a separate stop request; it never accepts an arbitrary cutscene handle or stops all cutscenes. Missing replies, target/session drift, native uncertainty and timeouts do not authorize resending a mutation or inferring completion. The independent native timer can still request its exact owned stop after a lost host reply. Missing stop events leave the serial reservation unresolved. World/load invalidation discards requests without replay.

An explicit `event_cutscene_stopped` matching the owned handle is a lifecycle observation. A requested operation may then report completed with that narrow scope. A refused stop remains refused even if its owner subsequently stopped; the separate stopped flag remains visible. Requesting an orbit never proves it was rendered, reached a desired angle, or maintained the requested distance.

`camera_observe` samples native `player.camera.yaw`, `pitch`, `zoom`, `external` and `isinfullscreencutscene`. The reply retains raw finite angle values and zoom; angular serialization units and reference frame are UNKNOWN. `achieved_pose_verified=false` and `target_distance_verified=false` remain explicit. The native tutorial establishes that angle/zoom changes are used to detect camera movement, but it does not establish a numerical world-space pose, target-relative distance, a yaw/pitch setter, or that these player-camera properties track every cutscene camera. Status never silently performs a new camera mutation. A completed read means a correlated sample, not a visual verdict.

## Source chain and confidence

The follow successor adds `follow_start {ship,distance,yaw,pitch,duration}`, using the existing native `Cutscene_follow_and_rotate` asset with identical start/end distance, yaw and pitch. It shares the orbit provider's one owned handle, serial reservation, context checks, timer, exact stop and ambiguity rules. Yaw is bounded to -360..360 and pitch to -90..90; these are requested native cutscene parameter values, not independently measured angles. Duration is 1..30 simulated seconds and distance 10..100000 native distance units. No asset is copied or authored.

READ `md/cinematiccamera.xml:2870–2901` supplies all six angle/distance endpoint parameters to the native camera-follow asset; `cutscenes/cutscene_follow_and_rotate.xml` connects each to its corresponding camera_follow begin/end field. Equal endpoints request a stable target-relative view rather than an orbit. Native `Angled_Camera_Keyframed_Shot` callers explicitly convert radians to degrees, but that proof belongs to that separate shot; this provider keeps follow-parameter calibration and raw player-camera serialization distinct. No setter echo is accepted as achieved pose. The existing native follow shot has its own duration in addition to the owned stop timer.

The cinematic-camera manager explicitly requests cinematicmode=true. This extension deliberately uses ordinary fullscreen playback: the same native follow asset is called without cinematicmode in `extensions/ego_dlc_timelines/md/scenario_waveattack_antigone.xml:535`. That second positive caller supports the display-mode distinction; it does not qualify the resulting runtime image.

Current follow controls total 63 passing actual LuaJIT/generated-loader/SDK/wire cases, zero skips. They retain the original 50 and add equal-endpoint/source wiring, local follow ownership and stop, invalid parameters and drift, plus immediate channel-disposal registration before fallible provider construction. A fresh canonical MD compile is required for this changed candidate; the original orbit receipt remains historical.

READ positive native sources (paths relative to the user's own reference):

- `extensions/ego_dlc_timelines/md/scenario_mining_1.xml:244–248` starts `OrbitParameterized` with target/distance/elevation and retains its result; lines 295 and 301 stop and observe that same handle. High confidence in the copied start/stop mechanism; runtime transport and timer execution remain unmeasured.
- `md/story_diplomacy_intro.xml:9087–9096` explicitly delays before testing `not player.isinfullscreencutscene` after prior interference. High confidence in the native guard, but it is sampled and not a global cutscene lock.
- `md/scenario_tutorials.xml:3497–3517` reads yaw/pitch/zoom and checks later changes; lines 3695–3701 compare angle changes against `1deg`. High confidence in the native angular semantic, UNKNOWN serialized units/world frame.
- `cutscenes/orbit parameterized.xml` uses the target, distance and elevation in an ecliptic-oriented repeating orbit with a 0→360 cycle over 48000ms, stopped by an event. This is the existing native asset, not a newly authored free-pose camera. The bounded timer is therefore necessary.
- `libraries/common.xsd:12796–12804` documents the stopped-event handle in param2. Schema compilation checks syntax only, not runtime event delivery.

Effective-corpus discovery was run only after a fresh x4eff verdict: 26 `OrbitParameterized` callers; 11 attributes containing `player.camera`; six attributes containing `isinfullscreencutscene` including its property definition. These are query item counts, not numbers of files. The named positive callers above ground this implementation. No assertion about absence of other camera APIs follows.

The existing `GetCameraRotation`/follow-camera offset reader remains separate. Native targetsystem uses raw roll to counterrotate UI elements; nearby trigonometric rotations suggest radians, but this extension does not promote that inference to a unit contract. `GetComponentScreenPosition` and target-system camera-distance observations remain possible separate projection evidence; no fabricated message/position identifiers are used here.

## Offline and runtime qualification

The initial functional suite has 50 passing actual LuaJIT/generated-loader/SDK/wire controls with synthetic MD replies, zero skips. It covers exact uint64 target preservation, source drift, bounded arguments, malformed identities/angles/flags, duplicate batches, lost replies, handle drift, refusal-vs-stopped classification and sticky retirement. Structural MD checks verify owned-handle stop, timer, foreign-scene guards and load/trigger markers. They do not execute MD or prove nested uint64 transport. Canonical MD compilation and final source-bound receipts are recorded separately before integration.

An approved runtime qualification must first prove LOAD and TRIGGER, then exact native target echo, owned-handle lifecycle including early/manual interruption, sampled angle behavior, bounded stop and no foreign-handle interference. Visual evidence may establish a useful view or visible orbit; it cannot silently waive the still-open exact yaw/pitch/distance/world-pose requirement. No automatic game launch, retry, focus change or capture is authorized by this source-only unit.
