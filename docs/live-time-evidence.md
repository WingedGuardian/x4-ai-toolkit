# Bounded host time evidence

`TimeEvidence(client)` uses an existing qualified AutomationClient and its actual ReadEvidence collector. `sample(issued_ship)` returns an opaque local handle after one fixed `time_state` read. There is no sleep, SETA start/stop, new connection, automatic retry or game action. The engine resolver still decides whether the supplied token is issued and is the currently occupied ship.

Each sample brackets the complete raw read with Python monotonic nanoseconds. It retains the actual raw receipt and transcript, source hashes, native time-state payload and separate host interval. Production callers cannot supply a clock or read-result dictionary. Explicit synthetic mode permits a test clock and retains SYNTHETIC provenance. This is not a security boundary against arbitrary same-user Python mutation.

`compare(first, second)` requires two distinct ordered handles from this owner, nonoverlapping host brackets, matching session/process/profile/build, matching requested and observed occupied ship, and matching sampled active/activity state. Game time and UI time must not regress in their own domains; envelope ordering is checked separately. No UI/game/host clock-origin equality is assumed.

For samples A and B, the unknown duration between the two native GetCurrentGameTime calls lies within the host bracket limits. The lower average reported game-clock advance per host second is `(B.game-A.game)/(B.host_end-A.host_begin)`; the upper is `(B.game-A.game)/(B.host_begin-A.host_end)`. Exact rational pairs and outward-rounded 24-significant-digit decimal strings are returned. Zero advance is a measured zero. Native clock resolution and floating-point reporting error are not independently qualified; the arithmetic is exact relative to the values actually reported.

These are historical endpoint observations, not a continuous SETA-state trace, achieved acceleration factor or simulation-outcome invariance result. Equal active endpoints do not establish that the state stayed unchanged between them. No current freshness is claimed by retrieving an old handle. Raw transcripts retain exported-replay limitations; local opaque handles preserve this collector's provenance.

The collector retains at most 16 samples. It inherits ReadEvidence's bounded frame/payload/retained-byte limits and source-replay checks. Nested collection, partial/failed reads, malformed state, source drift and foreign handles refuse. The native source basis is the existing `live_timecontrol.lua` observation: one GetCurrentGameTime call within its sampled occupied-ship/session checks. Native DLL execution and actual game timing remain untested by this unit.
