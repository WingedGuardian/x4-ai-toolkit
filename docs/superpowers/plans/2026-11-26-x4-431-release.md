## Findings that shaped the design (READ during planning, 2026-11-26)

1. `build-release.sh` zips with no top folder; core `release._safe_members` refuses such a zip. Hence the `X4AI/` prefix.
2. 4.3.0 installs have no update commands: the first real guarded update is 4.3.1 -> 4.3.2. Say so in the CHANGELOG.
3. Core `guarded_update.handle()` does not pass `run=`; the in-flight test calls `apply_update` directly.
4. An install that already fails the canary would lock itself (apply fails, rollback, old canary fails, `update-failed.json`). Run the canary on the installed state before stage and before apply; refuse (exit 2) with "fix x4doctor first".
5. `x4doctor` exits 4 on a healthy update (Codex re-approval TODO rows) and 3 without a reference: add `--update-canary`.
6. `x4guard.run_guard` turns a crash/timeout into a deny, so the Codex/OpenCode detached check runs in-process, outside it (as Skyrim's `engine._detached`).
7. GitHub `publishedAt` for v4.3.0 is 2026-11-21T00:12Z = 2026-11-20 US Eastern.
